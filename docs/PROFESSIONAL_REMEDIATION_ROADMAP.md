# JTWZ 专业版整改路线图

本路线图是 1.0.4 正式版的整改验收基线。未通过对应阶段的验收项，不得标记该阶段完成或创建正式 Release。

## 阶段 1：登录与核心可靠性

- [x] HTTP 公网部署不再错误下发仅限 HTTPS 的会话 Cookie
- [x] HTTPS 反向代理继续下发 `Secure` Cookie
- [x] 登录成功后通过 `/api/auth/me` 二次确认会话
- [x] 受保护接口返回 401 时统一清理前端登录状态
- [x] 重复错误提示去重
- [x] 密码规则在后台、API、安装器和 `jt` 中统一为最低 6 位
- [x] 修改密码后撤销其他设备会话
- [x] 增加 HTTP Cookie 与登录后续请求回归测试
- [ ] 使用真实浏览器完成公网 IP、HTTP、HTTPS 三种环境验收

## 阶段 2：前后台架构、主题与管理入口

- [x] 公开端与管理端拆分主题状态、样式入口和设计变量
- [x] 公开端使用 `jtwz.public.theme`
- [x] 管理端使用 `jtwz.admin.theme`，并支持独立偏好
- [x] 删除管理业务数据的 localStorage 双数据源
- [x] 增加运行时 `ADMIN_BASE_PATH`
- [x] 安装向导、后台和 `jt` 均可查看及修改管理入口后缀
- [x] 修改入口后旧路径返回 404，更新和恢复不得重置入口
- [x] API 继续使用同源 `/api`，不增加用户需要单独维护的 API 网站

## 阶段 3：公开站与管理后台业务闭环

- [x] 重做面向访客的公开首页、软件列表、详情、公告和错误页面
- [x] 公开站移除管理登录入口
- [x] 完成 SEO、移动端、加载、空数据、维护和失败状态
- [x] 管理端所有实体具备新增、查看、编辑、删除、启停和关联影响提示
- [x] 系统设置收敛为五个分类，每次只展示当前分类
- [x] 仪表盘异常提醒保持为单行横幅
- [x] 清除演示内容、演示文案和旧品牌标识

## 阶段 4：域名、网站发布与软件分发

- [x] 域名、DNS、跳转规则和 SSL 形成完整生命周期
- [x] 支持证书查看、添加、续期、修改、删除和失败诊断
  - [x] 证书记录、服务商签发、外部证书登记、到期状态、续期策略、删除和失败诊断已接通
  - [x] 自动续期调度、操作审计和完整备份数据表已接通
  - [x] 证书服务商 Webhook 已完成签发、续期、撤销、故障与重试的隔离集成验收；公网域名实测归入阶段 6 发布验收
- [x] 静态网站支持安全上传、预览、发布、下线、版本历史和回滚
- [x] 软件、版本、渠道和安装包建立完整关联
- [x] 支持大文件分片、断点续传、校验、暂停和删除
- [x] 长任务具备进度、结果、日志和失败恢复

## 阶段 5：完整备份、更新和部署

- [x] 迁移备份包含数据库、文件、网站版本、配置、账号、管理入口和校验清单
- [x] 备份可在另一台服务器直接上传恢复，失败自动回滚
- [x] 在线更新具备 Ed25519 签名校验、更新前备份、数据库迁移、健康检查和自动回滚
- [x] `jt` 菜单覆盖状态、日志、地址、管理后缀、域名、SSL、账号、备份、恢复、更新和卸载
- [x] 一键安装只使用公网地址，无域名时输出完整 IP 和端口
- [x] 宝塔、1Panel 解压后进入域名与管理员安装向导
- [x] Docker 提供持久化、非 root 运行、健康检查和 Caddy 反向代理配置
- [x] Git 仓库只保留源码；安装包、SHA-256 和签名更新清单由 GitHub Actions 放入 Release Assets

> Windows 已完成构建、迁移回滚与签名集成验收；公网 Linux、宝塔、1Panel、Docker 的真实安装/升级矩阵归入阶段 6 发布验收。

## 阶段 6：专业安全、验收与发布

- [x] 多管理员、角色权限、可选 2FA、会话设备管理和登录告警
- [x] CSRF、来源校验、上传校验、请求 ID、审计和敏感信息脱敏
- [x] 服务使用独立低权限系统用户
- [x] 后端按路由、服务、仓储、中间件、任务和迁移拆分
- [x] 本地真实浏览器完成公开站与 13 个后台路由的桌面/移动端验收（含 390px 溢出检查和控制台错误检查）
- [ ] 完成真实公网 IP、域名 HTTPS、宝塔、1Panel 和 Docker 测试矩阵
- [ ] 完成全新安装、旧版升级、跨服务器恢复和更新失败回滚测试
- [ ] 所有验收通过后更新版本、生成安装包、创建 Release 并推送

> 专业安全隔离测试已覆盖 RBAC、CSRF、请求 ID、TOTP、恢复码、设备会话、登录告警、上传文件签名与低权限 systemd 配置。GitHub `professional-quality-gate` 会在 Node 22/24、Docker、Compose 和部署脚本层持续回归；真实公网与面板环境仍必须在正式发布前完成验收。

## 版本策略

- `1.0.4`：阶段 1 紧急可靠性修复与签名发布链路。
- `1.1.0`：六个阶段全部验收后的专业版正式版本。
